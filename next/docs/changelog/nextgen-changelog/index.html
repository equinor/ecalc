eCalc NextGen

Changes to the NextGen YAML types: FLUIDS, PROCESS_SIMULATIONS, PUMP_SIMULATIONS and ENERGY_NETWORK. These are not available in legacy models, so they are not part of the release changelogs.

Unreleased​

Added​

  • PUMP_SIMULATIONS can be evaluated. Each period gets the stream distribution setting that was used and, for every pump, its rate, speed, recirculation, choke pressure drop and power, and whether it is within its chart. Pumps can be in parallel, with a common stream or a stream each, and in series. A pump with PRESSURE_CONTROL: NONE is not valid when its discharge pressure is above OUTLET_PRESSURE.

v15.9​

Added​

  • DEFINITIONS › PUMP_MODELS
  • ENERGY_NETWORK › UNITS › GENERATOR_SET › MODEL › GENERATORSETENGINEDEFINITION: A GENERATOR_SET can now be driven by a gas turbine or diesel engine (TYPE GAS_TURBINE_DRIVEN/DIESEL_ENGINE_DRIVEN) combined with a GENERATOR_EFFICIENCY, instead of only a direct power-to-fuel curve.
  • PUMPS
  • PUMP_PIPELINES
  • PUMP_SIMULATIONS
  • TIMELINE › PHASES: Named operating phases with a WHEN expression that references a time series or variable and evaluates to true or false in every period. Phases are not used by other parts of the model yet.

Changed​

  • INLET_STREAMS: A list in which each inlet stream is identified by its NAME, instead of a mapping keyed by name. Names must be unique. To migrate, drop each key and keep its entry, with its NAME, as a list item.
  • PROCESS_PIPELINES: A list in which each process pipeline is identified by its NAME, instead of a mapping keyed by name. Names must be unique. To migrate, drop each key and keep its entry, with its NAME, as a list item.

Removed​

  • ENERGY_NETWORK › UNITS › GENERATOR: replaced by ENERGY_NETWORK › UNITS › GENERATOR_SET. Renamed to GENERATOR_SET. The curve-based MODEL is unchanged; rename the unit's TYPE from GENERATOR to GENERATOR_SET.
  • FACILITY_INPUTS: FACILITY_INPUTS is only available in legacy models. Define compressor charts in DEFINITIONS.COMPRESSOR_MODELS, performance curves in DEFINITIONS.PERFORMANCE_CURVES and pump charts in DEFINITIONS.PUMP_MODELS, using FILE for data in a file.
  • PUMP_PROCESS_SIMULATIONS: replaced by PUMPS and PUMP_PIPELINES and PUMP_SIMULATIONS. To migrate, define the pump in PUMPS and its chart as a pump model in DEFINITIONS.PUMP_MODELS (or inline as MODEL), instead of referencing a chart in FACILITY_INPUTS. Place the pump in a pump pipeline in PUMP_PIPELINES. Move INLET to a liquid inlet stream in STREAM_DISTRIBUTION of a pump simulation in PUMP_SIMULATIONS, with RATE given as VALUE and UNIT, and OUTLET_PRESSURE to CONSTRAINTS of that pipeline. A choke is no longer implied: set PRESSURE_CONTROL to DOWNSTREAM_CHOKE to keep the previous results.
  • YAML_VERSION: Whether a model is NextGen or legacy is decided by how it is run, not by the YAML file. Remove YAML_VERSION from existing files.

v15.8​

Added​

  • ENERGY_NETWORK › UNITS › GAS_TURBINE › CHANGES
  • ENERGY_NETWORK › UNITS › GENERATOR › CHANGES

Changed​

  • ENERGY_NETWORK and PROCESS_PIPELINES: EVENTS on GENERATOR, GAS_TURBINE, DIESEL_ENGINE and process pipelines is renamed to CHANGES, so that EVENTS only refers to TIMELINE.EVENTS. Each change keeps REF, CHANGE_TYPE and CHANGE_TO. Using EVENTS gives a validation error pointing to CHANGES.
  • PROCESS_PIPELINES › CHANGES › CHANGE_FROM: No longer in use. Remove. This is detected automatically.

Removed​

  • ENERGY_NETWORK › UNITS › DIESEL_ENGINE › EVENTS: replaced by ENERGY_NETWORK › UNITS › DIESEL_ENGINE › CHANGES
  • ENERGY_NETWORK › UNITS › GAS_TURBINE › EVENTS: replaced by ENERGY_NETWORK › UNITS › GAS_TURBINE › CHANGES
  • ENERGY_NETWORK › UNITS › GENERATOR › EVENTS: replaced by ENERGY_NETWORK › UNITS › GENERATOR › CHANGES
  • PROCESS_PIPELINES › CHANGES › CHANGE_FROM
  • PROCESS_PIPELINES › EVENTS: replaced by PROCESS_PIPELINES › CHANGES

v15.7​

Added​

  • DEFINITIONS › PERFORMANCE_CURVES
  • ENERGY_NETWORK › SOURCES › DIESEL_SOURCE › LOWER_HEATING_VALUE
  • ENERGY_NETWORK › SOURCES › FUEL_GAS_SOURCE › LOWER_HEATING_VALUE
  • ENERGY_NETWORK › UNITS › DIESEL_ENGINE
  • ENERGY_NETWORK › UNITS › GENERATOR › EVENTS

Changed​

  • ENERGY_NETWORK: a compressor's EFFICIENCY in a DRIVE_TRAIN's MECHANICAL_EFFICIENCIES covers its share of the gearbox and couplings as well as its bearings and seals, not the driver's own losses. A compressor-only value, for example from a datasheet, should be multiplied by the gearbox efficiency.
  • ENERGY_NETWORK: a COMPRESSOR_SAMPLED unit's FILE has a MECHANICAL_POWER [MW] column, replacing FUEL and POWER, and its INPUT must provide mechanical power, e.g. a GAS_TURBINE or an ELECTRICAL_MOTOR. The gas turbine generated for a file with both FUEL and POWER is removed; declare a GAS_TURBINE as INPUT instead. See Migrate COMPRESSOR_SAMPLED for how to convert a FILE with POWER and FUEL into a MECHANICAL_POWER file and a gas turbine curve.
  • PUMP_PROCESS_SIMULATIONS: OUTLET_PRESSURE replaces REQUIRED_DISCHARGE_PRESSURE. It is the pressure requested downstream of the choke, which can be lower than the pump's discharge pressure. Results do not change.
  • DEFINITIONS › GENERATORS: Generators are now defined in DEFINITIONS > PERFORMANCE_CURVES.
  • DEFINITIONS › PERFORMANCE_CURVES › LOAD_TO_EFFICIENCY › LOWER_HEATING_VALUE: Set it on the fuel/diesel source this unit draws from instead.
  • DEFINITIONS › TURBINES: Gas turbines are now defined in DEFINITIONS > PERFORMANCE_CURVES.
  • ENERGY_NETWORK › UNITS › COMPRESSOR_SAMPLED: Removed NAME, the unit is named by COMPRESSOR. FILE must have a MECHANICAL_POWER column instead of FUEL and/or POWER, and INPUT must provide mechanical power.
  • ENERGY_NETWORK › UNITS › DRIVE_TRAIN: Removed NAME. A drive train is identified by SHAFT.

Removed​

  • ENERGY_NETWORK: NAME is removed from COMPRESSOR_SAMPLED and DRIVE_TRAIN. A COMPRESSOR_SAMPLED unit is named by its COMPRESSOR, which must differ from the names of sources and units, and a DRIVE_TRAIN is identified by its SHAFT.
  • DEFINITIONS › GENERATORS: replaced by DEFINITIONS › PERFORMANCE_CURVES
  • DEFINITIONS › PERFORMANCE_CURVES › LOAD_TO_EFFICIENCY › LOWER_HEATING_VALUE: replaced by ENERGY_NETWORK › SOURCES › LOWER_HEATING_VALUE
  • DEFINITIONS › TURBINES: replaced by DEFINITIONS › PERFORMANCE_CURVES
  • ENERGY_NETWORK › UNITS › COMPRESSOR_SAMPLED › NAME: replaced by COMPRESSORS › NAME
  • ENERGY_NETWORK › UNITS › DRIVE_TRAIN › NAME: replaced by COMPRESSORS › NAME
  • PUMP_PROCESS_SIMULATIONS › REQUIRED_DISCHARGE_PRESSURE: replaced by PUMP_PROCESS_SIMULATIONS › OUTLET_PRESSURE

v15.6​

Added​

  • ENERGY_NETWORK: a DRIVE_TRAIN can give the mechanical efficiency of each compressor on its shaft in MECHANICAL_EFFICIENCIES, as a COMPRESSOR and its EFFICIENCY, a number or an expression. A compressor demands its gas power divided by its mechanical efficiency as shaft power. A compressor not listed has efficiency 1.0, so existing results do not change.
  • DEFINITIONS › COMPRESSOR_MODELS
  • ENERGY_NETWORK › UNITS › DRIVE_TRAIN › MECHANICAL_EFFICIENCIES
  • PROCESS_PIPELINES › PROCESS_UNITS › COMPRESSOR › MODEL
  • TIMELINE

Changed​

  • DEFINITIONS: compressor models are defined in COMPRESSOR_MODELS, which replaces TYPE: COMPRESSOR process units in DEFINITIONS.PROCESS_UNITS. A compressor process unit gives its model with MODEL instead of TARGET, and a REBUNDLE event gives the new model with CHANGE_TO. Both take a model in place or the name of one in COMPRESSOR_MODELS. CHANGE_FROM is removed, since the model before the event is known.
  • DEFINITIONS › PROCESS_UNITS: Compressors can no longer be defined here. Other process units are defined inline in PROCESS_PIPELINES > PROCESS_UNITS.
  • PROCESS_PIPELINES › EVENTS › CHANGE_FROM: No longer in use. Remove. This is detected automatically.
  • PROCESS_PIPELINES › PROCESS_UNITS › COMPRESSOR › TARGET: Other PROCESS_UNITS can no longer be defined with TARGET.

Removed​

  • PROCESS_PIPELINES: DEFINITIONS.PROCESS_UNITS and TARGET are removed, so a process unit can no longer be reused from DEFINITIONS. Each entry in a pipeline's PROCESS_UNITS is a process unit given by its TYPE and that type's keys, and NAME on process units is removed. A compressor process unit has TYPE: COMPRESSOR and is the only process unit referred to by name, its COMPRESSOR. A constraint's PROCESS_UNIT must be the COMPRESSOR of a compressor process unit in its pipeline.
  • DEFINITIONS › PROCESS_UNITS: replaced by DEFINITIONS › COMPRESSOR_MODELS
  • ECALC_EVENTS: replaced by TIMELINE › EVENTS
  • PROCESS_EVENTS: replaced by TIMELINE › EVENTS
  • PROCESS_PIPELINES › EVENTS › CHANGE_FROM
  • PROCESS_PIPELINES › PROCESS_UNITS › COMPRESSOR › TARGET: replaced by PROCESS_PIPELINES › PROCESS_UNITS › MODEL

v15.5​

Added​

  • ENERGY_NETWORK: ELECTRICAL_CONSUMER and MECHANICAL_CONSUMER LOAD, and FUEL_GAS_CONSUMER and DIESEL_CONSUMER RATE, can each be a 1D curve (inline or FILE) looked up by a variable, instead of a direct expression. This replaces the current usage of the legacy TABULAR facility model, which is 1D (mostly rate vs. power) in practice.
  • COMPRESSORS: added the physical compressors in the model, each with a required unique NAME and an optional ALIAS. Compressor process units in PROCESS_PIPELINES and COMPRESSOR_SAMPLED units in ENERGY_NETWORK refer to a compressor with COMPRESSOR, which replaces NAME on compressor process units.
  • COMPRESSORS
  • ENERGY_NETWORK › UNITS › COMPRESSOR_SAMPLED › COMPRESSOR
  • ENERGY_NETWORK › UNITS › DIESEL_CONSUMER › RATE › CURVE › FUELTABLE
  • ENERGY_NETWORK › UNITS › ELECTRICAL_CONSUMER › LOAD › CURVE › POWERCURVE
  • ENERGY_NETWORK › UNITS › FUEL_GAS_CONSUMER › RATE › CURVE › FUELTABLE
  • ENERGY_NETWORK › UNITS › MECHANICAL_CONSUMER › LOAD › CURVE › POWERCURVE
  • PROCESS_PIPELINES › PROCESS_UNITS › COMPRESSOR › COMPRESSOR

Changed​

  • SHAFTS: each shaft lists the compressors on it with COMPRESSORS, which replaces SHAFT on compressor process units in PROCESS_PIPELINES. A compressor placed in a process pipeline must be on a shaft, and a DRIVE_TRAIN must drive a shaft whose compressors are all solved by a process simulation.
  • PROCESS_PIPELINES: a REBUNDLE event's CHANGE_TARGET must be the COMPRESSOR of a compressor process unit in the same pipeline. Other targets give a validation error listing the pipeline's compressors.
  • ENERGY_NETWORK › UNITS › DIESEL_CONSUMER › RATE: Added support to also load from curve.
  • ENERGY_NETWORK › UNITS › ELECTRICAL_CONSUMER › LOAD: Added support to also load from curve.
  • ENERGY_NETWORK › UNITS › FUEL_GAS_CONSUMER › RATE: Added support to also load from curve.
  • ENERGY_NETWORK › UNITS › MECHANICAL_CONSUMER › LOAD: Added support to also load from curve.

Removed​

  • FACILITY_INPUTS
  • FLUID_MODELS
  • FUEL_TYPES
  • INSTALLATIONS
  • MODELS
  • PROCESS_PIPELINES › PROCESS_UNITS › COMPRESSOR › SHAFT: replaced by SHAFTS › COMPRESSORS

v15.0​

Added​

  • ENERGY_NETWORK: capacities can be expressions, and capacity shortfalls are reported.
  • ENERGY_NETWORK: junctions allocate demand across multiple inputs, with per-input dispatch limits.
  • ENERGY_NETWORK: added COMPRESSOR_SAMPLED units. Sampled compressor tables extrapolate using the convex hull of the sampled data.

Changed​

  • PROCESS_SIMULATIONS: solver constraints use a relative tolerance, improving convergence for large values.

v14.0​

Added​

  • Added the ENERGY_NETWORK YAML types (sources, consumers, converters, junctions and cables), with a reference and examples.
  • ENERGY_NETWORK models are evaluated, so energy demand and flow are solved from the YAML.

Changed​

  • PUMP_PROCESS_SIMULATIONS: pump head is bounded by the maximum head of the pump chart, not only the minimum. Power and pressure no longer grow without limit outside the chart.

v13.12​

Added​

  • Added top-level FLUIDS, so process simulations can reuse named fluid compositions.

v13.10​

Added​

  • Added PUMP_PROCESS_SIMULATIONS for liquid pumps, calculated from a pump chart, an inlet stream and the required discharge pressure.

v13.8​

Added​

  • PROCESS_SIMULATIONS: added MIXER and SPLITTER units.

v13.4​

Added​

  • PROCESS_SIMULATIONS: added COMPRESSOR units, solved against the compressor chart.

Groundwork before v13.4​

Process simulations could not be run in these versions. They only contain internal preparation for PROCESS_SIMULATIONS.

  • v13.4.0: pressure control strategies (common and individual ASV, upstream and downstream choke), anti-surge strategies, a stream propagator, and ids for process units and systems.
  • v13.1.0: PROCESS_SIMULATIONS process constraints in the YAML schema, and the common ASV and recirculation solvers.
  • v13.0.3: a new process system interface. The top-level PROCESS_SIMULATIONS keyword was added to the YAML schema, without a mapping to the model.
